# 桌面版内置本地服务

Windows x64 的 Actions 安装包从 2.3.65.0 起携带自包含的 `AllLive.SignService.exe`。
直接启动 AllLive 即可，不需要运行 `聚合直播.ps1` / `SignService.ps1`，也不需要源码目录或另装 .NET。
安装流程仍是证书安装脚本、系统依赖和 MSIX。旧脚本保留用于原有开发方式，不参与新安装包的运行。

## 生命周期与通信

- 主窗口完成初始化并激活后，再在线程池启动服务；启动文件读写、就绪等待和健康检测不占用 UI 线程。首次相关请求共享同一个启动任务。
- Windows 预启动不启动服务。最小化、切后台、挂起不视为退出，也不使用会在挂起时过期的心跳。
- 主窗口和独立直播窗口共同拥有服务。新窗口创建期间也保留所有权；只有最后一个窗口关闭才写入停止通知。
- `Consolidated` / `CoreWindow.Closed` 中同步写入小型所有权文件，避免异步退出写入被挂起打断。
- 服务通过 `FileSystemWatcher` 接收停止/日志开关通知，通过持有的父进程句柄等待崩溃或强制结束。
- 停止后取消 HTTP 请求并正常释放资源；最多 5 秒后仅结束服务自身。不查找或终止其他 dotnet/脚本/服务进程。
- 每个应用会话使用随机标识和独立实例锁；新会话替换旧所有权会触发旧服务退出。
- 服务监听动态的 `127.0.0.1` TCP 端口。就绪文件带协议版本和会话标识，并用一次 HTTP 握手验证 UWP 的实际访问能力。
- 系统进程启动最多等待 10 秒；之后另给 .NET/Kestrel 冷启动和本机健康检测最多 20 秒。短暂的健康检测错误在就绪预算内重试。
- 首次启动失败会间隔 2 秒重试，启动/故障恢复合计最多 2 次。预算耗尽后，在设置中主动点击签名服务“检测”可重新尝试，无需重启 AllLive；自动检测、播放重连和窗口状态更新不会重置预算。
- 多窗口和并发检测共享同一启动/重试任务；没有空闲健康轮询。最后一个窗口关闭会取消等待，旧连接的延迟错误不会替换新会话。
- 服务初次读取所有权文件时，短暂的写入/文件锁冲突会在最多约 500 毫秒内重试，避免直接退出。
- 默认的 `127.0.0.1:8788` / `localhost:8788` 签名地址由客户端映射到随包服务。自定义路径、端口、查询参数和远程地址保持原行为。
- 本机请求复用禁用代理和自动重定向的 HTTP 客户端。控制/签名请求需要会话标识；原生播放器使用不可猜测的独立流 URL。
- MSIX 声明同包双向 `LoopbackAccessRules` 和 `privateNetworkClientServer`，不调用管理员回环豁免命令。

所有权和就绪文件在应用 `LocalState/LocalService` 内，只用于应用自身通信，不是用户配置。
服务校验父进程确实是同一安装目录下的 `AllLive.UWP.exe`。启动失败或通信权限异常可在签名服务设置中检测状态。

## 窗口最大化与还原

桌面版直播间底栏的「最大化／还原」与系统标题栏按钮使用相同的窗口命令，保留标题栏、任务栏和还原尺寸。
UWP 通过当前视图的 `ICoreWindowInterop` 获取窗口句柄，内置服务校验句柄属于已验证的父进程，
并确认 CoreWindow 及其窗口框架后，发送有 500 毫秒超时的 `WM_SYSCOMMAND`。
不按窗口标题或当前前台窗口查找目标，多直播窗口互不影响。

此接口仅在随包托管模式下开放，沿用会话鉴权；旧独立签名服务不开放窗口控制。
状态刷新由窗口尺寸变化触发，合并 200 毫秒内的连续变化，没有常驻状态轮询。
操作期间禁止重复提交，页面关闭时取消请求并解除事件订阅；日志仍受运行日志开关控制。
不携带桌面服务的通用/Xbox 构建隐藏此按钮，不留占位。

## 资源限制

- ASP.NET 使用工作站 GC，取消默认控制台/请求日志。签名 SDK 文本在首次使用时加载。
- 签名请求最多并行 2 个，满额立即返回 503，不排无限队列。
- Jint 限制语句数、内存和执行时间，并绑定请求/应用停止取消信号。
- QuickJS 使用类型明确的 API、64 MiB 引擎内存上限、3 秒执行预算和原生中断处理；每次请求结束释放上下文及运行时。
- B 站转发最多并行 8 路，使用流式转发及池化缓冲，不缓存完整直播。
- 上游响应头等待最多 15 秒；读写停滞最多 30 秒。持续有数据的正常直播没有总时长限制。
- 每次 B 站注册产生独立流 URL，后续注册不会覆盖其他窗口的重连地址。
- 注册表最多 64 条。仍有活动连接的条目保留；断开后空闲超过 10 分钟的条目在后续请求时回收，不为清理增加常驻轮询。

## 日志

应用“运行日志”开关同时控制服务诊断；开关关闭时不执行消息格式化或文件写入。
服务日志位于应用 `LocalState/log/LocalService.log`，达到 5 MiB 或跨天时滚动，最多保留 5 个归档。
`AllLive.log` 记录主窗口激活耗时，以及服务每次启动的阶段（Owner/Launch/Readiness/Health）、尝试次数、耗时、异常类型和 HRESULT。服务端 `LocalService.log` 补充所有者验证、HTTP 就绪和宿主错误。
诊断不记录 Cookie、签名、所有权标识或完整播放 URL。
启用日志不是服务工作的前提。

## 构建与验证

Actions 先执行 `.github/scripts/Test-LocalService.ps1`，然后自包含发布 win-x64 服务，再以
`IncludeLocalService=true` 和 `LocalServicePublishDir=<发布目录>` 构建 UWP。
`Package.Desktop.appxmanifest` 用于这条桌面构建；默认 `Package.appxmanifest` 继续用于通用/Xbox 构建，不携带 FullTrust 组件。
两个清单必须保持相同 Identity 和版本；测试会校验发布者计算出的包族名与回环规则一致。
服务不能使用裁剪或单文件发布，以免破坏脚本引擎和原生依赖。

签名后的 MSIX 还会通过 `.github/scripts/Test-BundledService.ps1` 检查：实际桌面清单、FullTrust 能力、
自包含运行时配置和全部服务发布文件确实进入安装包。

自动验证覆盖：端点映射、会话隔离/容量/过期、真实 Jint/QuickJS 中断、内置抖音脚本执行、
转发字节完整性/停滞取消、所有权文件停止、父进程退出，以及日志开关。
启动回归检查还覆盖并发共享、后台启动、首错重试、预算耗尽、手动恢复、关闭取消和所有权文件短暂写入。
UWP 源码继续做 C# 7.3 语法检查，包含桌面条件编译分支；完整 UWP 编译由 Actions 完成。

安装新包后的运行态验收仍需覆盖：

1. 不运行旧脚本，直接启动应用，两个默认签名服务状态可用。
2. 打开两个 B 站窗口，关闭主窗口或其中一个直播窗口，其余播放正常。
3. 最小化/恢复不重启服务；关闭最后一个窗口后服务退出；立即重新打开也正常。
4. 任务管理器结束 AllLive 后服务自行退出；结束服务后下一次相关请求至多触发一次重启。
5. 网络中断、主播下播、切换直播间时，连接数量与 CPU 不持续攀升。
6. 关闭运行日志后，服务日志不再增长；在无手工回环豁免的新安装环境验证本机通信。
7. 底栏最大化/还原与系统标题栏按钮交替使用，标签和图标同步；两直播窗口间操作互不影响，还原后尺寸正确。

编译、离线脚本测试和包内容检查不能替代这些 UWP 生命周期/实际直播验证，也不构成 mihomo 高 CPU 根因已被实测证明的结论。
