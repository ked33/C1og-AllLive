# 斗鱼账号与实际画质（2.3.81.0）

入口：设置 → 账号 → 斗鱼 → 扫码登录。使用斗鱼 App 扫码确认，退出登录也在此处。

播放清晰度菜单保留平台返回的原始档位。旁边的实际画质说明来自当前播放地址对应的服务端 `rate`，例如“实际：蓝光4M（请求：原画2K60）”。接口缺少有效 `rate` 时显示“实际画质未确认”，不根据 URL、档位请求值或名称猜测。它表示平台确认的档位，不等于对视频分辨率/码率的实时测量。

## 登录与凭据

- 二维码申请、串行轮询、JSONP 登录回调使用独立 CookieContainer；刷新或关闭对话框会取消旧流程。超时及过期后可手动刷新。
- 登录流程只接受 HTTPS 斗鱼域名的回调与重定向，且只在当前流程仍有效时提交账号。
- Cookie 使用 Windows `DataProtectionProvider("LOCAL=user")` 加密，以事务写入应用本地目录的 `douyu-account.dat`。不写入普通设置、日志、备份或同步数据。
- 登录 Cookie 中的设备标识用于签名和 HTTP 请求；H5 凭据必须成对出现，避免混用 Web 与 H5 会话。续期字段 `LTP0` 不发送给取流接口。
- 启动时恢复本地账号并尝试续期。网络失败保留原账号；登录或退出后刷新已打开的斗鱼房间。退出删除加密凭据并恢复原匿名设备标识，旧异步结果不得覆盖新账号。

## 取流与画质

- 改用官方 `websec/getEncryption` 与 `getH5PlayV1`，本地计算 MD5 签名。旧版外部 JS 签名不参与斗鱼取流，相应设置隐藏；历史配置备份字段仍可读取。
- 描述符按账号版本缓存，最多五分钟，提前三十秒失效；失败时最多刷新重试一次。账号切换即使设备标识不变，也不得复用旧描述符。
- 不预取所有清晰度：仅解析当前请求档位，各线路最多两个并发、总预算十五秒、单线路八秒。
- 档位使用稳定 `rate` 标识并保留平台顺序。播放地址携带请求档位、实际档位和实际名称，避免共享“最后一次响应”造成串房间/串线路。
- 优先选服务端确认的请求档位；未满足时选第一个已确认档位组；全部未知时保留未知组。同组多线路供原有播放器恢复使用，不混合实际画质不同的线路。
- 本次不增加斗鱼 FLV 提前续流，不修改其它平台的取流接口。

## 验证

`.github/scripts/Test-PlaybackRecovery.ps1` 包含离线协议/策略测试：设备标识与会话隔离、Cookie 裁剪、扫码状态、回调限制、取消、新版签名向量、表单编码、描述符缓存、并发限制、账号切换废弃旧结果以及实际画质分组。

本机只做上述检查与匿名官方接口验证；UWP/WinRT、XAML、签名打包由 GitHub Actions 验证。真实账号扫码确认、重启后的凭据解密、登录后高画质权限及持续播放需安装新版验证。
